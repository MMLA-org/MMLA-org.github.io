MMLA 不是给模型再接一个“记忆库”，而是规定一次经验怎样取得改变未来的权力：生成时只读旧记忆；片段明确结束后才回看；每个候选都针对某条旧记录完整构造；最后只能整行提交，或者让原状态一位不变。 MMLA is not another “memory store.” It specifies how an experience earns authority over the future: generation reads only old memory; retrospective review starts only after explicit closure; each candidate is built as a complete replacement for one old row; and the system either commits that whole row or preserves every bit of state.

01 / 为什么是记忆WHY MEMORY

长上下文能重放历史，
却不会替历史分配权威。 Long context can replay history.
It cannot decide what deserves authority.

MMLA 把已经完成的局部经历压缩成少量、可寻址、可替换的记忆行。每次写入都必须回答：这段经历是否值得留下？它应该覆盖哪一行？如果证据不足，能否明确不写？ MMLA turns completed local experience into a small set of addressable, replaceable memory rows. Every write must answer: is this worth keeping, which row should it replace, and can the system explicitly decline to write when evidence is weak?

这层状态不是无限的上下文缓存，也不是永久固化的参数知识。它是一个带生命周期、带版本、带回退路径的中间层。 This state is neither an unbounded context cache nor permanent parametric knowledge. It is a middle layer with a lifecycle, versioning, and a fallback path.

可以把三者想成三种不同的东西：上下文像桌面上的临时材料，模型参数像长期训练形成的习惯，MMLA 记忆像一份有限的工作笔记。工作笔记应该能查、能改，也应该允许把不可靠的内容留在桌面上而不是存进去。 Think of three layers: context is material on a temporary desk, model weights are habits built through long training, and MMLA memory is a limited working notebook. A working notebook should be inspectable and editable, and unreliable material should be allowed to stay off the notebook.

02 / MMLA 的核心机制THE CORE OF MMLA

核心不是“多一块记忆”，
而是严格规定未来怎样被改变。 The core is not “more memory.”
It is a strict contract for changing the future.

MMLA 把一次记忆更新缩成一个可验证的状态转移：先生成，片段结束后再整理；对每个可能被替换的旧记录分别构造完整候选；系统最后只能提交一整条新记录，或者让原状态完全不变。任何新状态都只能被之后的生成读取。 MMLA reduces a memory update to one verifiable state transition: generate first and consolidate only after closure; build a complete candidate separately for every old row that might be replaced; then either commit one whole new row or leave the state exactly unchanged. Only later generation may read the new state.

生成中GENERATE

只用旧记忆向前生成Generate causally from old memory

当前 token 只能读取片段开始前已经公开的 M。系统同时留下输出、随机选择和读过哪些记忆的不可变回执。Each token can read only M exposed before the segment began. Outputs, random choices, and memory reads receive immutable receipts.

片段结束CLOSE

明确封口，再允许回看Close explicitly before review

只有一个有上限的局部片段正式结束后，整理器才可以同时看见片段的前后文。封口规则不能依赖尚未出现的后缀。Only after a bounded local segment formally closes may the consolidator inspect it bidirectionally. Closure cannot depend on a suffix that has not yet appeared.

整理CONSOLIDATE

把完成内容拆成有序事件Turn completed content into ordered events

整理器只处理已经封口的视图，把它拆成数量有上限、顺序固定、可去重的事件。后台完成得快慢不能改变事件的逻辑先后。The consolidator processes only the closed view and emits a bounded, ordered, deduplicable event list. Worker timing cannot change logical order.

逐事件处理FOLLOW THE ACTUAL BRANCH

后一个事件必须看见前一个事件真的做了什么Each later event sees what the earlier event actually did

如果前一个事件替换了某行，后一个事件就在更新后的 M 上重新构造候选；如果前一个事件选择不写，后一个事件就从原状态继续。不能拿过期快照批量决定。If an earlier event replaced a row, the next event rebuilds candidates from the updated M. If it chose NULL, the next event continues from the unchanged state. Decisions cannot be batch-made from a stale snapshot.

针对目标造候选TARGET-CONDITIONED CANDIDATES

每个可能被替换的旧行，都有自己的完整候选Every possible target gets its own complete candidate

候选不是一段悬空文本。构造器同时看事件、目标旧行、当前分支记忆和片段摘要，回答“如果替换的就是这一行，新记录应该完整长什么样”。A candidate is not free-floating text. The constructor sees the event, the target's old row, current branch memory, and segment summary, asking what the complete replacement for this specific row should be.

可信装配TRUSTED ASSEMBLY

模型写语义，系统补齐并守住权力字段The model proposes meaning; the system owns authority fields

可信装配器补上身份、租户与访问范围、版本、保护状态、来源、删除标记、回退关系和一致性回执。模型不能通过生成文本给自己扩大权限。A trusted assembler adds identity, tenant and access scope, version, protection, provenance, tombstone status, rollback lineage, and a consistency receipt. Generated text cannot grant itself more authority.

先检查，再比较CHECK, THEN CHOOSE

不合法的先排除，剩下的和“不写”一起比较Exclude illegal actions, then compare the rest with exact NULL

越界、过大、无权限、版本过期或不一致的候选直接失去资格，评分再高也不能恢复。可行动作只剩若干完整行提交和一个精确不写。Oversized, unauthorized, stale, or inconsistent candidates are removed before scoring and cannot be revived by a high score. The feasible set contains complete-row commits plus exact NULL.

原子提交ATOMIC COMMIT

一次只改变一整行，完成后才让未来读取Change one whole row, then expose it to the future

被选中的完整行一次发布，未选中的行逐位保留；选择不写时整个 M 原样保留。片段内全部事件结束后，新版本才可供后续 token 使用。The selected complete row publishes in one step while every untouched row is preserved bit for bit; exact NULL preserves all of M. The new version becomes readable only after all segment events finish.

训练老师与真实运行分开SEPARATE THE TRAINING TEACHER FROM LIVE USE

训练可以复盘以后发生了什么；上线选择必须对未来失明Training may study what happened later; live choice must remain future-blind

只存在于训练阶段TRAINING ONLY

从同一个冻结时刻，重放每个可行动作Replay every feasible action from one frozen snapshot

训练老师把相同因果前缀接到多种真实后续，并分别重放“替换这行”“替换另一行”“保持不变”。它计算之后的任务损失、错误记忆泄漏、挤掉旧记忆的损害、写入与服务成本，用来教会评分器估计长期后果。The teacher groups multiple realized continuations sharing the same causal prefix and replays “replace this row,” “replace another row,” and “leave unchanged.” It prices later task loss, stale-memory leakage, displacement harm, write cost, and service cost to teach long-run action value.

把核心走一遍A COMPLETE WORKED EXAMPLE

“Alice 已从巴黎搬到柏林”到底怎样变成未来可读的记忆？How does “Alice moved from Paris to Berlin” become future-readable memory?

这个例子不展示实验结果，只展示状态语义。重点不是抽取出“柏林”两个字，而是系统怎样安全地替换关于 Alice 的那条权威记录。This is a state-semantics example, not an experiment. The point is not merely extracting “Berlin,” but safely replacing the authoritative row about Alice.

更新以前BEFORE

权威记录写着 Alice 在巴黎The authoritative row says Alice is in Paris

这条旧记录带着自己的身份、当前版本、权限、来源和回退关系。The old row carries its identity, current version, permissions, provenance, and rollback lineage.

片段封口CLOSED SEGMENT

完成内容说明 Alice 已搬到柏林Completed content states that Alice moved to Berlin

这句话在生成时只属于当前上下文。片段结束后，它才被整理成一个有序更新事件。During generation it belongs only to context. After closure it becomes an ordered update event.

针对旧行构造TARGET-CONDITIONED

为 Alice 的旧行造一条完整替代记录Build a complete replacement for Alice's old row

语义内容改为柏林；可信系统给出新版本、同一身份、允许的访问范围、这次搬迁的来源和可回退关系。Semantic content changes to Berlin; the trusted system supplies the new version, same identity, allowed scope, move provenance, and rollback relation.

最后选择FINAL CHOICE

替换 Alice 的整行，或者完全不写Replace Alice's whole row, or write nothing

还可以为其他允许被替换的行构造各自候选，但必须分别比较；不能先写内容、以后再补版本或权限。Other eligible targets may get their own candidates, but each is compared separately. Content cannot publish first while version or permissions arrive later.

如果提交IF COMMITTED

Alice 的旧行被一整条柏林记录替换，其他所有行不变；这条新记录只影响之后的读取。Alice's old row is replaced by one complete Berlin row, every other row stays fixed, and only later reads can observe it.

如果不写IF EXACT NULL

巴黎记录连同当前版本逐位保留。它不会被清空、不会新增版本，也不会偷偷变成删除记录。The Paris row and its current version remain bit-for-bit unchanged. Nothing is cleared, versioned, or silently turned into a deletion.

如果要删除IF DELETING

删除本身也是一次正式提交：发布一条带删除标记和来源的新记录。删除与“不写”不是一回事。Deletion is itself a commit: a new row with a tombstone and provenance. Deletion is not NULL.

它定义的对象OBJECT DEFINED

一个明确封口的有界片段、一组顺序稳定的事件，以及位于封口之后的公开时刻。生成轨迹和读取回执一旦产生就不可修改。An explicitly closed bounded segment, a stably ordered event list, and an exposure point strictly after closure. Generated traces and read receipts are immutable.

什么会破坏它WHAT BREAKS IT

根据未来后缀决定封口、缺少稳定锚点、事件编号会漂移、跨段内容无限累积、读取共享可变缓存，或把试运行状态直接拿给真实生成使用。Suffix-dependent closure, missing anchors, unstable event identity, unbounded carry, shared mutable read caches, or reuse of speculative state in live generation.

它没有声称IT DOES NOT CLAIM

它不保证整理器读懂了语义，不保证候选值得写，也不等于策略学习。它只保证“什么时候可以回看、什么时候可以影响未来”在因果上说得通。It does not guarantee semantic understanding, useful candidates, or policy learning. It guarantees that review and later influence obey a coherent causal boundary.

什么叫“权威”WHAT “AUTHORITATIVE” MEANS

如果改动某个状态后，系统以后读到的对象、值、删除状态、权限或允许的下一次变化会不同，而且不需要重新验证当前行，那么这个状态就是权威状态。搜索索引、缓存和向量视图只能是可重建的派生物。State is authoritative if changing it can alter the later-read object, value, deletion status, permissions, or allowed transition without revalidating the current row. Search indexes, caches, and vector views are reconstructible derivatives.

一行里必须一起存在什么WHAT ONE ROW CONTAINS

MMLA–RTT Dual State

Φ / 策略状态POLICY STATE

数值型、可训练，作用是改变后一次动作怎样产生。它由反馈驱动的策略更新写入，有自己的更新完成时刻、漂移限制、版本与回退。Numerical and trainable, it changes how a later action is generated. A feedback-driven policy updater writes it, with its own completion time, drift limit, version, and rollback.

M / 权威记忆AUTHORITATIVE MEMORY

有界、可寻址、带版本与来源，作用是改变以后可以读到什么。它只能由可信记忆提交器通过完整行替换写入。Bounded, addressable, versioned, and provenanced, it changes what may be read later. Only the trusted memory committer writes it through whole-row replacement.

一次尝试怎样读取HOW AN ATTEMPT READS THEM

一次尝试固定自己读到的策略版本和记忆版本，得到一致的组合；固定组合只是避免中途漂移，不会把两边变成同一个所有者或同一种状态。An attempt pins the policy version and memory version it reads as one consistent pair. Pinning prevents mid-attempt drift but does not create joint ownership or collapse the types.

论文完成的理论工作WHAT THE PAPER ESTABLISHES

  • 为两条状态线分别规定写入者、读取者、权限、寿命、重置、回退、资源账和故障范围；只改 M 被分类为记忆适应，不是策略训练。Assigns separate writers, readers, privileges, lifetimes, resets, rollbacks, resource ledgers, and failure domains; an M-only edit is memory adaptation, not policy training.
  • 证明两边在互不读取对方中间结果时可以交换顺序，并给出独立回退、策略漂移、记忆污染和两者交互误差的条件与边界。Gives conditions for commutation when neither side reads the other's intermediate result, plus independent rollback and bounds for policy drift, memory contamination, and interaction error.
  • 给出“策略更新开或关 × 记忆更新开或关”的四组干预设计，用来分辨各自作用和共同作用；只看最终输出不能完成这种归因。Defines a four-cell intervention—policy update on/off crossed with memory update on/off—to identify individual and joint effects; final outputs alone cannot provide this attribution.
严格 RTT 在这里怎样判断STRICT RTT HERE

只有较早反馈确实非平凡地更新 Φ，更新在同题结束前完成，后一次真正新的尝试又读取了更新后的 Φ，才属于严格 RTT。记忆 M 更新得再多，也不能替代这条证据。Strict RTT requires earlier feedback to nontrivially update Φ, completion before the same problem ends, and a genuinely fresh later attempt reading the updated Φ. No amount of M mutation substitutes for this witness.

有效策略状态不能藏东西EFFECTIVE POLICY STATE

需要什么证据EVIDENCE REQUIRED

需要尝试、反馈、更新开始与完成、版本读取、重置和停止的回执；还需要交换、冻结、重置或随机开关更新的干预。只看输入输出轨迹无法识别内部到底是学习、搜索还是记忆变化。Receipts are needed for attempts, feedback, update start and completion, version reads, resets, and stopping, plus swap, freeze, reset, or randomized update interventions. Input-output traces alone cannot identify learning versus search or memory adaptation.
